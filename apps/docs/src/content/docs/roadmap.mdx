## 0.1.0 (shipping)

The lazy random-access core. One parser running over four readers, with image
HDU support end to end.

- Header parsing covers fixed and free-format cards, `CONTINUE` long
  strings, `HIERARCH` long keywords, indexed access (`NAXISn`, `TFORMn`),
  duplicate keyword handling, and lenient recovery.
- HDU enumeration covers primary plus extensions, with recognition of
  `IMAGE`, `BINTABLE`, and ASCII table extensions, and lookup by
  `EXTNAME`/`EXTVER`.
- Readers ship as `BytesReader` (in-memory), `BlobReader` (browser
  `Blob`/`File`), `NodeFileReader` (`fs`-backed, behind
  `@fits-js/core/node`), and `HttpRangeReader` (HTTP `Range`, with LRU
  paging and `If-Range`).
- Image data is decoded by `readImage`, with region cutouts, BITPIX
  scaling (`BZERO`/`BSCALE`), the unsigned-integer convention, and
  `BLANK` to `NaN`.

## Next

- BINTABLE and ASCII table decode, with column accessors.
- Tile-compressed images (`RICE_1`, `GZIP_1`, `GZIP_2`, `HCOMPRESS_1`,
  `PLIO_1`).
- `.fits.gz` support via `DecompressionStream`.
- Writer side: `openFitsForWrite`, primary + extension write, header
  mutation.

## Out of scope

- WCS coordinate transforms (a separate library job).
- Random groups (detected and rejected).
- Built-in image viewer or canvas rendering helpers. The library returns
  decoded typed arrays. Rendering choices belong in user code or example
  packages like
  [`examples/reference-viewer`](https://github.com/prustic/fits-js/tree/main/examples/reference-viewer).
